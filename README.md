# BodyClocks

BodyClocks is an R Shiny application for exploring circadian transcriptomic datasets. It currently brings together 93 datasets (29 mouse and 64 baboon) processed into a common set of rhythmicity statistics, expression profiles, functional annotations and STRING protein-association networks.

[Launch BodyClocks](https://www.bodyclocks.org) · [Data and analysis pipeline](https://github.com/Michal0110/BodyClocks_data)

## Main features

### Circadian Explorer

- Browse datasets by species and tissue, search for genes, inspect RAIN rhythmicity statistics and plot temporal expression profiles.
- Select genes from the results table, network or enrichment terms. Optional connecting lines and sinusoidal fits support visual interpretation; the fitted curve is a visual aid rather than a separate rhythmicity test.
- Explore STRING v12 protein-association networks at confidence thresholds of 700 or 900. Edge width represents the STRING combined confidence score; switching confidence changes the network but not the enrichment analysis.
- Browse significant GO Biological Process, KEGG, Reactome and WikiPathways terms, highlight their associated network nodes and view annotations in node tooltips.
- Choose between two enrichment backgrounds:
  - **Genes tested in this dataset**: genes eligible for rhythmicity testing after dataset-specific preprocessing and successfully mapped to STRING.
  - **All STRING proteins**: the species-wide STRING proteome.

The enrichment-background setting changes the available terms, term-based highlighting and node tooltips. It does not change network edges or node positions.

### Dataset Comparison

Compare any two datasets from the same species. The module summarises rhythmic-gene overlap relative to chance, absolute and clock-relative phase relationships, permutation-based phase concordance, expression profiles and shared functional-enrichment terms. Dataset Comparison uses the all-STRING enrichment background; a pair-specific background selector is not currently provided.

## Data and reproducibility

The application reads precomputed RDS artifacts generated by the separate [BodyClocks data pipeline](https://github.com/Michal0110/BodyClocks_data). That repository contains the source-data manifest, dataset-specific preprocessing, RAIN analyses, annotation and STRING-processing code. Dataset-specific inclusion and rhythmicity criteria are documented there because they reflect the design and statistical power of the original studies.

Network and enrichment results are generated before deployment using STRING v12. Enrichment terms are retained at FDR ≤ 0.05. The application does not call STRING or rerun transcriptomic analyses during an interactive session.

## Running locally

The project is developed with R 4.5.2 and uses `renv` for dependency management. App data are stored with Git LFS, so retrieve them before starting the application:

```bash
git lfs install
git lfs pull
Rscript -e 'install.packages("renv", repos = "https://cloud.r-project.org")'
Rscript -e 'renv::restore(prompt = FALSE)'
Rscript -e 'shiny::runApp(".", host = "127.0.0.1", port = 7860)'
```

Then open <http://127.0.0.1:7860>.

Alternatively, run the containerised application:

```bash
docker compose up --build
```

## Updating generated data

App data should be regenerated in `BodyClocks_data`, validated there and then synchronised into this repository rather than edited manually:

```bash
cd ../BodyClocks_data
Rscript run_analysis.R --fail-fast
Rscript -e 'source("R/validation_utils.R"); validate_rds_exists()'
rsync -a results/shiny_data/ ../BodyClocks/data/
```

## Repository structure

- `app.R`, `ui.R`, `server.R` — application entry point and top-level Shiny components.
- `explorer_module.R` — Circadian Explorer interface and server logic.
- `comparison_module.R` and `comparison_functions.R` — Dataset Comparison functionality.
- `datasets.R` — dataset registry and display metadata.
- `functions.R` — shared data loaders, plotting and enrichment helpers.
- `data/` — generated application artifacts; source processing belongs in `BodyClocks_data`.
